ISCC content-code under local transformations

A durability measurement of the ISCC image Content-Code (ISO 24138). Companion to the Article 50(2) C2PA teardown. Nothing is uploaded; the script runs on your machine.

The C2PA teardown measured the metadata layer: a quality-95 JPEG re-save stripped the manifest on 30 of 30 runs. This measures the other side of the same question. An ISCC Content-Code is derived from the pixels, not attached as metadata, so a re-encoder has nothing to strip. The measurement records how far the recomputed code drifts, in bits, under the same class of local transformations.

Reading

Under compression, re-encoding, resizing and format conversion the Content-Code drifts by 0 to 2 bits out of 256. The transformation that strips the C2PA manifest completely leaves the Content-Code effectively unchanged. Under cropping the code drifts by 24 to 110 bits: geometric edits move it far, and the amount is not constant across assets.

What this does not measure

  • The Content-Code only. The ISCC Data-Code and Instance-Code are exact and change on any re-encode by design; they are not part of this question.
  • Benign local transformations, not adversarial attack. A soft hash is tunable; a colliding or distance-inflated code can be crafted on purpose. These numbers say nothing about that case.
  • Whether a file is AI-generated. A Content-Code is a content fingerprint, not a provenance claim and not a detector.

Two results that cut against the reading

  • Cropping breaks the anchor. A content-derived code is durable against pixel-level operations and not against geometric ones. A publisher who crops a thumbnail moves the code by tens of bits. Durability here is conditional on the transformation class, and cropping is a common one.
  • The grayscale row is not robustness. It reads 0 because the Content-Code algorithm converts to grayscale during preprocessing, so a grayscale input is not an independent transformation. It is listed for completeness, not as a strength.

The number is not a verdict

Whether a given drift counts as "the same content" is a threshold, not a fact in the data. The same re-encode reads 0 on one asset and 2 on another; crop_5 reads 24, 56 and 86 across the three. A single fixed cutoff does not separate the classes identically for every asset. The distance is measured; where the line sits between match and non-match is a choice that has to be set, published and dated, not read off privately.

Reproduce

Single dependency beyond the standard library: iscc-core (the ISO 24138 reference implementation) and Pillow. Point the script at any directory of images; the shape holds on your own files.

pip install iscc-core Pillow
curl -sO https://nous-lang.org/a50/iscc/iscc_degradation.py
sha256sum iscc_degradation.py
python3 iscc_degradation.py /path/to/your/images

Content-Code drift is measured, not interpreted. A code that reproduces within a few bits records similarity; it is not a provenance claim, and the match threshold is an external decision. The script, its hash, the library versions and the corpus hashes are here so a reader can disagree with the measurement rather than with the author.
