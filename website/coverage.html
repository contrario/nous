Coverage Proof & the Farkas Certificate

A NOUS dossier has always carried a cost proof: a guarantee, checked before execution, that a governed agent cannot exceed its declared spend. Coverage is the second proof beside it — that over a declared risk threshold, no input escapes the declared blocking-policy net. And it is checkable by a third party with nothing but standard-library arithmetic.

"The verifier does not trust the producer. It verifies the producer."

What is proven, before execution

  • Cost — the total cost cannot exceed the declared cost_cap across every execution path in the proven bound. Universal, not sampled.
  • Coverage — over the declared threshold region, no input satisfies the threshold while escaping every blocking policy. No gap in the net.
HONEST BOUNDARY

Coverage proves there is no gap in the declared blocking net — not that the agent cannot misbehave. The policies are monitors, and the signed evidence attests the declared governance is sound and was in force. This is coverage, not impossibility. NOUS claims exactly what it can sign, and refuses the rest.

The obligation

For a threshold T and blocking signals s1 ... sk, coverage is the unsatisfiability of T AND NOT(s1 OR ... OR sk) over the reals — "an input that crosses the threshold but trips no blocking policy". If that is unsatisfiable, no such input exists. If it is satisfiable, the solver returns a concrete counterexample — a gap — and NOUS refuses to sign:

$ nous verify --smt aml_transaction_governance.nous \
    --coverage-threshold "amount > 10000" --manifest-out out/m.json
PROVEN: total_cost <= $0.50 across all execution paths
Coverage PROVEN: no gap over threshold 'amount > 10000'

$ nous verify --smt aml_transaction_governance.nous \
    --coverage-threshold "amount > 5000" --manifest-out out/gap.json
REFUSED: coverage not proven (verdict=refuted); no manifest written.

A transfer of 5,001 satisfies "over 5,000" but escapes rules that only fire above 10,000 and 50,000. The 5,000–10,000 band is a gap NOUS will not certify. Fail-closed: no evidence is produced for an ungoverned system.

Checked without a solver

Re-running the same solver does not raise trust — a solver bug is reproduced, not caught, and it forces an auditor to install and trust a solver. So the coverage claim ships as a Farkas certificate: for this linear-real fragment, an unsatisfiable system has a list of non-negative rational multipliers that combine its inequalities into a numeric contradiction — here, 0 < 0. That list is the certificate, and checking it is multiply-and-add over fractions: about forty lines of standard-library Python. The solver is used once, at build time, to find the multipliers; it is never needed to check them.

1 — THE BANK'S AI
Probabilistic execution
Build any agent. NOUS sits above as a governance shell and proves the cost ceiling and the coverage net before any model call. If it cannot prove it, it refuses to sign.
2 — THE ARTIFACT
The signed dossier
One self-contained package, Ed25519-signed. Tamper one byte and the signature breaks. Offline and immutable — it never phones home.
3 — THE AUDITOR
Asymmetric verification
Verifies on a disconnected laptop. No NOUS, no solver, no network. The coverage proof is checked by stdlib rational arithmetic; it collapses to 0 < 0.
ZERO VENDOR TRUST · ZERO SOLVER DEPENDENCY · PURE MATH

Two dependency contexts

The asymmetry is the point. The producer needs the solver; the auditor needs neither it nor NOUS.

# producer (writes the proofs + dossier)
pip install 'nous-lang[smt]'

# auditor (verifies offline) -- cryptography only, no solver, no NOUS
pip install 'cryptography>=42'
cd dossier && python3 verify_offline.py
OK   Ed25519 signature verified
OK   Farkas certificate verified by rational arithmetic, no solver (0 < 0)
VERDICT: PASS

The offline verifier checks, fail-closed: the Ed25519 signature, the source and proof file hashes (an O(1) provenance gate before any proof check), then the Farkas certificate by arithmetic. z3, if installed, runs only as an optional second opinion — the verdict does not depend on it. The human-inspectable coverage.smt2 stays in the dossier as a cross-check.
