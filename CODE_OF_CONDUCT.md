# Code of Conduct

NOUS is a small, focused project. This Code of Conduct exists
so that everyone interacting with it knows what is expected,
what is not tolerated, and how to escalate when something
goes wrong.

It applies to every space where the project lives: the
GitHub repository (issues, pull requests, discussions,
reviews), the project website, any official social-media
account, and any in-person or remote event held under the
project's name.

---

## What we expect

- **Be civil.** Disagreement is welcome; rudeness is not.
- **Argue about ideas, not people.** "This approach has a
  race condition because..." is a review. "This is amateur
  hour" is not.
- **Be patient.** The maintainer responds in batches, not
  continuously. A delay is not a slight.
- **Assume competence.** Contributors come from many
  backgrounds; not everyone is a working software developer.
  The project itself is maintained by a chef-turned-architect.
  Condescension about background is out of place.
- **Keep things on topic.** Issues and pull requests are for
  the project, not for unrelated debate.
- **Take responsibility for mistakes.** Apologise, learn,
  move on. Nobody expects perfection.

---

## What is not tolerated

- Personal attacks, insults, or slurs of any kind.
- Harassment, intimidation, or stalking, public or private.
- Sexualised language or imagery, or unwelcome sexual
  attention.
- Doxxing or publication of private information without
  explicit consent.
- Sustained off-topic disruption of issues or pull requests.
- Bad-faith engagement: deliberate misreading, sealioning,
  brigading, or coordinated harassment.
- Threats of violence, real or implied.

---

## Reporting

If someone breaks this Code of Conduct, please report it.
Two channels:

1. **Public:** open a GitHub issue describing what happened.
   Use this when the behaviour was already public and you
   want the response to be public too.
2. **Private:** send a direct message to the maintainer
   through GitHub
   (https://github.com/contrario). Use this when the
   behaviour was private, when you fear retaliation, or when
   you want the report handled discreetly.

There is no email address promised in this document. The
project is single-maintainer, and email expectations would
create a service level the maintainer cannot honour. GitHub
DMs and issues are the supported channels.

When you report, please include:

- What was said or done.
- Where it happened (link to issue, PR, comment, etc).
- When it happened.
- Whether the behaviour is ongoing.
- Whether you want the report kept private.

You will not be retaliated against for reporting in good
faith.

---

## Enforcement

The maintainer is responsible for enforcement and has the
final say on this project. Possible responses, in increasing
order of severity:

1. **No action.** The reported behaviour did not break the
   Code, in the maintainer's judgement.
2. **Private note.** A private message asking the person to
   change the behaviour.
3. **Public note.** A reply on the issue or PR explaining
   that the behaviour is not acceptable here.
4. **Edit or hide.** Removal or hiding of specific comments
   that violate this Code.
5. **Temporary block.** A time-limited block from
   participating in the project's spaces.
6. **Permanent ban.** Removal from all project spaces.

The response is proportional to the severity, the impact on
others, and whether the person has already been warned. A
single tone-deaf comment usually gets a private note. A
pattern of harassment gets a ban.

---

## Scope

This Code applies to behaviour in the project's spaces,
listed at the top of this document. It also applies when
someone represents the project externally (for example,
speaking at a conference under the project's name, or posting
from an official account).

This Code does **not** apply to general conduct elsewhere on
the internet. The maintainer is not the internet police. If
someone is unpleasant on their personal blog, that is between
them and their blog's audience, not a NOUS project matter.

---

## Limits

This Code is a description of expectations, not a contract.
The maintainer reserves the right to update it as the project
evolves; substantive changes will be announced in the
project's CHANGELOG.

This Code is not a substitute for the law. If a behaviour is
illegal in the relevant jurisdiction, contact the
appropriate authorities; the maintainer cannot and will not
investigate criminal conduct.

This Code does not create any legal obligation between the
project, the maintainer, contributors, or third parties
beyond what already exists in the project's MIT License.

## Attribution and acknowledgements

This Code draws on the spirit of the Contributor Covenant

from scratch to fit a single-maintainer project with a
non-standard contribution model. It is intentionally short.
